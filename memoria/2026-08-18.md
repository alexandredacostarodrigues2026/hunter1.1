# Parte 8 — ACHADO REAL: CSS "font-size" nunca funcionou em nenhum st.dataframe/data_editor do app

## Resumo Executivo

Pedido do usuário, depois da redução pra 8px na Parte 7: **"fonte
grande ainda. diminua"**. Investigando por que uma redução de fonte
"não fazia efeito" — descoberta de um bug estrutural que afetava
TODAS as ~30 tabelas do app que já tinham recebido pedido de "diminuir
fonte" ao longo de toda a sessão (desde antes de 2026-08-17): a regra
CSS `[data-testid='stDataFrame'] * { font-size: Npx; }`, usada em
TODO lugar, **nunca teve efeito visual real** nas células.

## Causa Raiz (investigação técnica)

`st.dataframe`/`st.data_editor` (Streamlit 1.58) renderizam via
**glide-data-grid**, que desenha cabeçalho E células dentro de um
`<canvas>` — não como texto de DOM comum. CSS `font-size` normal NÃO
alcança conteúdo desenhado em canvas. Confirmado inspecionando o
bundle JS do próprio Streamlit instalado
(`runtime/Lib/site-packages/streamlit/static/js/DataFrame.*.js`): o
componente React seta, via `style` INLINE, um conjunto de CSS CUSTOM
PROPERTIES próprias do glide-data-grid (`--gdg-base-font-style` pras
células, `--gdg-header-font-style` pro cabeçalho, `--gdg-marker-font-
style` pro índice, `--gdg-editor-font-size` pra edição — formato
"{peso} {tamanho}px", com "400 13px"/"600 13px" como padrão visual) —
é ISSO que precisa ser sobrescrito (com `!important`, pra vencer o
`style` inline), não `font-size` comum.

## Funcionalidades Implementadas

- **`_aplicar_fonte_dataframe(chave_container, tamanho_px)`** (nova,
  helper único): gera o `<style>` correto — mantém `font-size`
  (inofensivo, só nunca fazia nada sozinho) + as 4 variáveis
  `--gdg-*` corretas, todas com `!important`.
- **Todas as ~30 chamadas antigas** (`st.markdown("<style>...font-size:
  Npx...")`) trocadas por `_aplicar_fonte_dataframe(chave, tamanho)` —
  substituição em massa via script Python (regex, 3 variantes de
  formato: key literal em 2 linhas, key literal em 3 linhas, `f-string`
  com variável Python tipo `chave_container`), verificada item a item
  antes/depois. Os 2 casos de `st.metric` (`bc3_kpis`, KPIs miniatura
  das Grades 7.3.3) foram DEIXADOS INTOCADOS — `st.metric` é DOM
  normal, `font-size` já funcionava corretamente ali.

## Testes Realizados

- Compilação limpa (`py_compile`) depois da substituição em massa.
- `streamlit.testing.v1.AppTest` em 11 páginas diferentes do app
  (Cruzamento por Valor/Produto, RN1 Física/Produto/Simulada,
  Consolidado 733, Estágio 8/9, Produtos Alvo Salvos, Consolidado 11,
  Relatórios) — 0 exceções em TODAS; 9 das 11 confirmaram a nova CSS

  nesse teste por faltar pré-requisito de dados, não por erro).
